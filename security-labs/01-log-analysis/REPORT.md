# 보안취약점 로그분석 실습 보고서

최정원 | 교육 실습 | 기간 2025.09.17~2025.09.30 | 정리일 2026.11.09

## 목적

네트워크 캡처와 세션 흐름, IDS 경보, IIS·syslog 기록을 연결해 보안 이벤트를 살펴보는 교육 실습입니다.

## 기존 포트폴리오에 기록된 내용

도구: Argus, tcpdump, Snort, Windows Log Parser, Log Parser Studio

- 트래픽 캡처 및 PCAP 분석
- Argus를 이용한 세션 흐름 분석
- Snort를 이용한 ICMP·Log4j 관련 탐지 실습
- IIS 요청 패턴 및 syslog 기록 분석

위 내용은 [기존 노션 기록](https://app.notion.com/p/2ae09f14126e800a8e7ae19738a000ea)에 있는 실습 요약입니다. 작업 명령·설정·원본 결과와 본인의 독립 수행 범위는 아직 확인되지 않았습니다. 팀장이나 실무 운영 역할을 임의로 부여하지 않습니다.

## 작업 과정을 보여주는 정리 방법

다음 절차는 기록을 보완하거나 재실습할 때 사용할 확인 방법입니다. 당시 수행한 절차나 이번에 완료한 테스트로 간주하지 않습니다.

1. 실습 환경의 시간대와 캡처 위치를 기록합니다.
2. 원본 PCAP·로그를 보존하고 비식별 사본을 만듭니다.
3. 정상 구간과 의심 구간을 나눠 주소·시간·프로토콜을 비교합니다.
4. IDS 경보가 가리키는 패킷·요청을 대조합니다.
5. 경보 발생 사실과 공격 성공 여부를 구분해 결론을 씁니다.

## 증거별 검토 항목

| ID | 항목 | 확인할 내용 | 필요한 자료 |
|---|---|---|---|
| L01 | PCAP | 시간·출발지·목적지·프로토콜 | 원본 PCAP 및 캡처 환경 |
| L02 | IDS 경보 | 규칙 ID·시각·대상·해당 패킷 | Snort 버전·설정·경보 |
| L03 | 웹 로그 | 경로·응답 코드·반복·정상 요청 비교 | 비식별 IIS 로그·조회식 |
| L04 | 흐름 분석 | 패킷과 세션의 시간·주소 상관관계 | Argus 출력·사용 명령 |

기존 실습 캡처 1장을 추가했습니다. 아래 점검 항목 전체가 증명되는 것은 아니며, 화면으로 확인되는 범위는 별도 해설을 참고합니다. [증거 목록](evidence-register.csv)에 상태를 분리해 기록했습니다.

## 사례를 설명할 때

의심 요청이나 IDS 경보 한 건을 선택해 시간, 규칙 ID, 관련 패킷, 정상 요청과의 차이를 함께 제시합니다. 실제 파일이 확보되기 전에는 사건을 임의로 만들어 쓰지 않습니다.

[사례 기록 양식](../templates/CASE_RECORD.md)에는 상황, 직접 한 일, 도움받은 방법, 실제 결과를 작성합니다. 기억하지 못하는 원인은 확인되지 않음으로 남기고, 제안한 개선책을 적용 완료로 바꾸지 않습니다.

## 결과와 한계

기존 페이지의 ‘실제 공격 탐지 전 과정 수행’이라는 표현만으로 Log4j 악용 성공이나 탐지 정확도를 입증하지 않습니다. 원본 로그·규칙·실행 결과가 없어 탐지율·오탐률을 계산하지 않았습니다.

기존 실습 요약 외에 노션의 원본 캡처 1장을 확보했습니다. 화면에서 확인되는 작업과 추가 증거가 필요한 주장을 구분했습니다. 취업 제출 시 수행 사실을 뒷받침할 자료가 있는 사례부터 강조하는 것이 적절합니다.
