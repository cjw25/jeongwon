# 실습 증거 정리 방법

## 한 사례에 필요한 묶음

환경·버전 → 정상 기준 → 직접 작업한 명령·설정 → 원본 출력 → 해석 → 수정한 경우 재확인 순으로 묶습니다. `evidence-register.csv`에 실제 경로와 수행일을 기록합니다.

## 주제별 확보 우선순위

1. 로그분석: PCAP 또는 로그 한 건, 관련 경보·조회식, 시간과 주소의 연결 근거
2. 웹: 정상 요청과 변경 요청, 비식별 응답, 계정 권한, 수정 후 동일 요청 결과
3. 네트워크: 망 구성, 서비스 리슨 목록, 스캔 원본, 패킷 프레임 번호
4. DB: 실제 제품·버전, 계정 권한, 허용·거부 출력, TLS 세션과 사용 코드

## 관찰과 결론 구분

- IDS 경보는 공격 성공과 다릅니다.
- 열린 포트는 취약점 확정이 아닙니다.
- 401·500은 원인을 확정하는 정보가 아닙니다.
- TLS 사용과 인증서 검증은 별도로 확인합니다.
- Prepared Statement 사용만으로 시스템 전체의 SQL Injection 제거를 주장하지 않습니다.

## 공개 파일

실제 계정, 토큰, 쿠키, 인증 헤더, 비밀번호, 고객·주유소 식별 정보는 제외합니다. 실습용 가상 식별자로 바꾼 경우 비식별 사본임을 표시합니다. 원본은 공개 저장소에 올리지 않고 필요 시 로컬에서 보존합니다. 샘플 데이터는 반드시 합성 예시로 표시하고 과거 실행 결과와 섞지 않습니다.
