# 웹 해킹 실습 프로젝트 실습 보고서

최정원 | 교육 실습 | 기간 2025.08.26~2025.09.04 | 정리일 2026.11.09

## 목적

교육용 웹 환경에서 요청·응답을 비교하며 SQL Injection·XSS·IDOR의 발생 조건과 방어 관점을 학습한 실습입니다.

## 기존 포트폴리오에 기록된 내용

도구: Burp Suite, OWASP Juice Shop

- SQL Injection·XSS·IDOR 시나리오 실습
- 프록시를 통한 요청·응답 확인 및 변조
- 취약점 리포트 작성

위 내용은 [기존 노션 기록](https://app.notion.com/p/2ae09f14126e804c8f73d5a75e0047b4)에 있는 실습 요약입니다. 작업 명령·설정·원본 결과와 본인의 독립 수행 범위는 아직 확인되지 않았습니다. 팀장이나 실무 운영 역할을 임의로 부여하지 않습니다.

## 작업 과정을 보여주는 정리 방법

다음 절차는 기록을 보완하거나 재실습할 때 사용할 확인 방법입니다. 당시 수행한 절차나 이번에 완료한 테스트로 간주하지 않습니다.

1. 본인 소유의 격리된 교육용 환경과 테스트 계정만 사용합니다.
2. 버전·기능·계정 권한과 정상 요청을 기록합니다.
3. 입력 또는 대상 식별자를 바꿔 응답과 서버 처리를 비교합니다.
4. 인증·인가, 입력 처리, 출력 문맥 중 관찰 근거가 있는 부분만 기술합니다.
5. 방어 적용 후 같은 요청과 정상 기능을 다시 확인합니다.

## 증거별 검토 항목

| ID | 항목 | 확인할 내용 | 필요한 자료 |
|---|---|---|---|
| W01 | SQL Injection | 기준 요청·변경 요청·서버 처리 차이 | 비식별 요청/응답과 서버 근거 |
| W02 | XSS | 입력 반사와 실제 브라우저 실행 구분 | 입력 위치·출력 문맥·실행 근거 |
| W03 | IDOR | 두 테스트 계정의 소유권·접근 허용 비교 | 계정 A/B 권한표·요청/응답 |
| W04 | 재검증 | 수정 전후 동일 조건에서 비교 | 수정 코드·정상 기능 회귀 결과 |

현재 모든 항목은 원본 증거 미확보 상태입니다. [증거 목록](evidence-register.csv)에 상태를 분리해 기록했습니다.

## 사례를 설명할 때

IDOR 사례를 정리한다면 A·B 계정, 각 소유 데이터, 요청한 객체와 실제 반환 데이터를 짝지어야 합니다. 로그인이 됐다는 사실과 해당 객체에 접근할 권한은 구분합니다.

[사례 기록 양식](../templates/CASE_RECORD.md)에는 상황, 직접 한 일, 도움받은 방법, 실제 결과를 작성합니다. 기억하지 못하는 원인은 확인되지 않음으로 남기고, 제안한 개선책을 적용 완료로 바꾸지 않습니다.

## 결과와 한계

원본 요청·응답, 실습 난이도와 버전, 본인 작성 리포트가 확보되지 않았습니다. 세 취약점의 성공·수정 완료나 실제 서비스 침해 경험으로 표현하지 않습니다. HTTP 오류만으로 취약점을 확정하지 않습니다.

현재 결론은 해당 주제의 교육 실습 요약이 존재한다는 수준입니다. 취업 제출 시 수행 사실을 뒷받침할 자료가 있는 사례부터 강조하는 것이 적절합니다.
